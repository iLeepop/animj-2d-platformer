# 01 — 游戏设计

> 坐标、命名、Z 层、目录见 `00-conventions.md`。物理手感数值见 `06`，渲染见 `07`，格式见 `03`。

## 1.1 定位

一句话：**在一张由房间串成的大地图里，用小动物在像素平台上跳跃，拾取道具穿越地形，率先/依次抵达唯一终点；通关时间决定分数。**

| 项 | 值 |
|---|---|
| 类型 | 2D 平台跳跃（单机 / **本地双人** / **局域网联机**，单房间最多 4 人） |
| 视角 | 侧视，正交，**每个玩家一个视角**：联机时各自跟随自己的角色；本地双人左右分屏；视野小于一个房间 |
| 美术 | 像素风，瓦片/角色均为 32×32；道具当前用占位色块 |
| 输入 | 键盘（方向 + 跳跃 + `E`）为主，手柄为辅；本地双人共享键盘（键位见 `06` §6.1.6）；不做触屏/鼠标操作 |
| 目标平台 | Windows 桌面（本机 win32）；跨平台不是本阶段目标 |
| 单局时长 | 示例关卡速通 ≈ 3–10 分钟；时长取决于路线与道具使用 |

## 1.2 核心循环

```mermaid
flowchart LR
  A[进入关卡] --> B[计时开始]
  B --> C[平台跳跃 + 拾取/覆盖道具]
  C --> D{触碰终点?}
  D -- 否 --> C
  D -- 是 --> E[锁定该玩家通关时间]
  E --> F{所有玩家都已到达?}
  F -- 否 --> C
  F -- 是 --> G[结算：每名玩家的时间与分数]
```

- 循环粒度是**整张关卡**，不是房间。房间只用于地图组织、相机视野与加载裁剪。
- 房间**没有目标**：没有 `goals`、没有房间通关、没有房间奖励。
- 玩法驱动是**终点**与**限时**：路线选择、道具取舍、失误代价都体现在通关时间上。

## 1.3 角色

| 项 | 约定 |
|---|---|
| 形象 | 小动物（占位资产用纯色方块 + 耳朵/眼睛色块），32×32 精灵 |
| 碰撞体 | AABB，尺寸见 `06`；**玩家之间不碰撞**（可互相穿过，只与瓦片碰撞，见 `06` §6.11） |
| 基础能力 | 左右移动、跳跃、**可变跳跃高度**（早松手跳得矮）、coyote time、jump buffer |
| 道具能力 | 由拾取的道具临时提供：**高跳 / 快跑 / 双跳**（§1.5、`06` §6.12） |
| **不做**（明确排除） | 攻击、冲刺、滑翔、爬墙、抓取/搬运、生命值/血量 |
| 伤害 | **无血量概念**。碰到 `Hazard` 即死亡 → 回到存档点/出生点，并**清除道具 buff**（§1.7） |
| 朝向 | 左右翻转 sprite（`Sprite::flip_x`），不改变碰撞体 |

> 道具是**临时能力**，不是永久解锁：换道具即换能力，10 秒后或死亡时清除。

## 1.4 终点

- 关卡里有且只有 **1 个 `goal` 实体**（`03` V23），可以是任意房间。
- 任一玩家的 AABB 与 `goal` 区域相交 ⇒ **该玩家**锁定自己的通关时间（每人只记第一次），并继续游戏等待其他玩家。
- 所有在场玩家都到达终点 ⇒ 进入 `GameComplete` 结算。单人时等价于「碰到终点即获胜」。
- 终点不再按房间判定，也不依赖任何条件列表。

## 1.5 道具

| 项 | 约定 |
|---|---|
| 拾取 | 玩家 AABB 与 `item` 区域相交即拾取（外扩 `PICKUP_INFLATE`）；一次性 `item` 销毁，`item_spawner` 生成的道具隐藏并进入重生倒计时 |
| 生成器 | `item_spawner` 在自身位置生成道具；被拾取后固定 **1.5 秒**重新生成（`ITEM_RESPAWN_SECS`，主机权威） |
| 容量 | **每个角色同时只携带一个道具**；再次拾取**覆盖**原有道具（不叠加、不排队） |
| 持续 | 拾取后 buff 持续 **该道具类型配置的秒数**（默认 10 秒，`Level.items[*].duration_secs`），超时自动清除；覆盖拾取会重置为满 |
| 类型 | `SuperJump`（高跳）、`Speed`（快跑）、`DoubleJump`（双跳），枚举见 `03` §3.5 |
| 贴图 | 按 `ItemKind` 在关卡级 `items` 中**共享**设置 `sprite` 并框选 32×32 格；不按单个实体设置（`04` §6） |
| 编辑器 | 底部「道具」面板统一编辑三种道具的贴图、贴图格与持续时间 |
| 生效 | 只影响携带者的物理参数副本（`06` §6.12），不改变全局常量 |
| 死亡 | **清除**当前道具 buff；避免死亡后仍带着限时能力（`01` §1.5） |
| 存档 | 不持久化道具（它不是收集/解锁内容，只是关卡内的临时状态） |
| HUD | 显示焦点玩家当前道具名与耗时 |
| 视觉 | 优先使用编辑器设置的 PNG；未设置时用不同颜色的 12×12 色块（`04` §6） |

## 1.6 通关、计时与分数

| 项 | 约定 |
|---|---|
| 计时起点 | 进入 `GameState::Playing` 后的第一个固定步；暂停/加载不累计（`run::advance_run_clock`） |
| 计时粒度 | 固定步 1/60 秒累加；显示保留两位小数 |
| 通关时间 | 每名玩家**第一次**触碰终点的时刻；不可改写 |
| 结算条件 | 所有在场玩家都已有通关时间（单人 = 触碰终点） |
| 分数公式 | `score = round(max(0, SCORE_BASE − 通关秒数 × SCORE_PER_SECOND))`；常量归本节，代码在 `config`/`run` |
| 结算展示 | 每名玩家的通关时间与分数；未到达者显示「未完成」 |
| 联机 | 主机权威计时与终点判定；快照同步 `run_elapsed` 与每名玩家的 `finish` |

> 分数常量：`SCORE_BASE = 10000`、`SCORE_PER_SECOND = 10`（`crates/game/src/run.rs`）。改数值必须同步本节。

## 1.7 重生点与存档点

- 存档点是关卡里的 `checkpoint` 实体（`03` §3.4）：玩家站在其区域内按 `E` 即激活，**立即写入存档**。
- 死亡回退优先级：
  1. 已激活的存档点（可跨房间）；
  2. 关卡出生点：`player_spawn` 所在房间的重生点（房间 `spawn` 字段 > 引擎默认值，见 `02` §重生点）。
     与死亡时所在房间无关；不记录"最后安全位置"。
- 激活的存档点持久化在 `SaveData` 中；重启游戏后直接从存档点所在房间/位置继续（`05` §5.11）。
- 玩家死亡 → 传送后速度与跳跃状态清零、**道具 buff 清除**（完整清单见 `06` §死亡重置）；计时**不暂停**（死亡是速通成本的一部分）。

## 1.8 关卡与房间规模

| 项 | 值 | 说明 |
|---|---|---|
| 示例规模 | `10 × 3 = 30` 房间 | 纵向 3 行构成多条路线 |
| 建议上限 | 单个关卡 ≤ 64 房间 | 超过后关卡加载与全量渲染策略需要重新设计（见 `07` 裁剪） |
| 房间尺寸 | 16×16 瓦片 = 512×512 像素 | D5，见 `00` §0.3 |
| 起始房间 | 由 `.level.ron` 的 `start` 指定 | 起房间内必须有 `player_spawn` |
| 终点 | 全关卡任意房间，恰好 1 个 | 不要求与起始房间相连（由关卡设计保证可达） |

### 地形语言（设计约束）

| 元素 | 默认用法 | 说明 |
|---|---|---|
| `#` 实心 | **绝大多数地形** | 四面阻挡：墙、地面、台阶、悬空平台一律用它 |
| `=` 单向平台 | **隐藏通道专用** | 只能从上方站住、下方可穿过。用于"跳上去发现秘道"的少数点位，**不作为普通平台** |
| `^` 尖刺 | 危险 | 不阻挡，接触即死亡 |
| `*` 装饰 | 背景 | 无碰撞 |

- 房间网格是**二维**的：除左右相邻外还有**上下纵深**（`row = 0` 为最上一行，`00` §0.3）。
- 垂直相邻的两个房间在瓦片网格上**无缝**：上房底行与下房顶行直接相邻，所以"下房顶行留坑 = 通往上房 / 上房底行留坑 = 掉进下房"是最简单的纵深连通方式（`02` §2.1、`03` V18 会以 Warning 提示边界不连续）。
- 单向平台的**数量必须远少于**实心块：它本身就是"这里有秘道"的线索，用多了玩家就不再相信地板。
  目前唯一合规用法：竖井内的上行台阶（`world_01` 两处竖井各 6 级，2 格间距 = 64 px 可逐级上跳）与
  `rooms[20]` 的隐藏通道（同为单向台阶）。
- 道具放置：示例关卡在出生房间 `r00` 放两个「快跑 / 高跳」生成器用于引导与贴图验证，`r03` 集中展示三种一次性道具；关卡设计应保证任意路线都能在需要高跳/双跳的位置附近拿到对应道具。

### 非目标（本阶段明确不做）

- 敌人 AI、战斗、Boss。
- 多关卡串关流程（关卡选择界面已落地；关卡之间不串进度、不做解锁链）。
- 公网联机、账号、匹配大厅、排行榜、成就、云存档、反作弊（局域网联机已进入范围，见 M8）。
- 手柄重绑定 UI、多语言、无障碍。
- 移动端 / Web 构建。
- 程序化关卡生成。
- 手柄之外的输入设备（鼠标操作角色）。
